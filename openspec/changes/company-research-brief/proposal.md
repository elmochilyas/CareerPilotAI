## Why

Candidates cannot prepare confidently when a saved opportunity shows only the job description. Phase B adds a **Company Research Brief**: a concise, source-backed company profile attached to a confirmed `JobOpportunity`. It unlocks truthful application documents and interview preparation (Phases E/I) while enforcing explainability (fact vs. inference), provenance, and SSRF-safe external fetching. It builds directly on the existing `companies` / `job_opportunities` relation that is currently unused.

## What Changes

- Audit existing `companies` (`research` JSON, `researched_at`, `company_id` on `job_opportunities`) and `JobOpportunityConfirmed` flow (preview → confirm); reuse existing columns/models where clean, extend only where proven insufficient.
- Implement deterministic company identity normalization and safe association: confirmed opportunities are associated with a `Company` when identity is reliable; ambiguous names preserve opportunity data without corrupting company records and still allow limited research.
- Define and persist a versioned structured **research brief** (overview, products/services, technology/engineering context, role context, recent relevant information, candidate preparation, sources) with `status`, `generated_at`, `version`, `fallback_reason`, and per-claim provenance.
- Enforce **fact vs. inference vs. unknown** separation: confirmed facts are source-cited, inferences are explicitly labeled, unknown fields are `unknown`; never present inference as fact.
- Store per-claim provenance: `url`, optional `title`, `retrieved_at`, claim/section association, source type, confidence / fact-or-inference marker; prefer official site → official blog/careers → job posting → reputable secondary; no fabricated citations.
- Build a reusable **SSRF-safe fetcher** (HTTPS preferred, block localhost / loopback / private IPv4 & IPv6 / link-local / cloud metadata `169.254.169.254`, validate DNS for every redirect, limit redirects/timeout/response size/content types, safe user-agent, deny `file://`/`ftp://`/non-HTTP). Failures produce a safe failed/limited state, never crash the opportunity.
- Provide **paste/manual fallback**: when fetching is unavailable, synthesize a limited brief from trusted `JobOpportunity` description, `company.website` supplied by candidate, and pasted about content; mark brief as `limited`.
- Implement async pipeline: `ResearchCompanyJob` dispatched `afterCommit`, dedicated queue `company-research`, `timeout`/`tries`/`backoff`, idempotency key, `WithoutOverlapping` per company/opportunity, states `not_researched` → `processing` → `completed|failed|limited`, safe `failed()` handler, retry, and request-ID propagation (`X-Request-ID` / `RequestIdContext`).
- Constrain AI to summarization/structuring of retrieved/pasted evidence only: prompt delimits untrusted content, structured schema validation, reject fabricated URLs/facts/technologies/funding/revenue/news; on schema/provider failure produce deterministic basic brief and record `fallback_reason` plus prompt version / provider / model / latency / token metadata.
- Support **refresh/regenerate** with `researched_at` tracking, freshness age display, configurable staleness threshold (e.g., 30 days), and concurrent-research prevention (409 `research_in_progress`).
- Expose authenticated async API consistent with `GET /api/v1/opportunities/{opportunity}/matches` pattern: `GET` company-research (status + brief), `POST` start research, `POST` refresh; 202 for async start, polling/status body, problem-details errors, ownership/confirmed-opportunity checks, cross-user 404.
- Extend `OpportunityDetailPage` with a compact Company Research section/tab/card covering all states (`not_researched` CTA, `processing`, `completed`, `failed` retry, `limited` explanation), displaying the six brief sections, fact/inference badges, and per-section source indicators (domain + retrieved date, expanded URL/title). No raw JSON dump, no `v-html`.
- Define freshness strategy (stored `researched_at`, UI age label, `stale` flag after threshold, manual refresh only — no scheduler yet) and a clean `CompanyResearchService` interface for future Interview Preparation / Cover Letter consumers.
- Harden against prompt injection and malicious content: treat all fetched/pasted content as data, delimit in prompt, ignore embedded instructions; add regression tests for `localhost`, `127.0.0.1`, `::1`, `169.254.169.254`, RFC1918, redirect-to-private, oversized/unsupported/timeout/malformed cases.

## Capabilities

### New Capabilities

- `company-research`: Async company research domain — Company association & normalization, structured brief content model, fact vs. inference vs. unknown enforcement, per-claim provenance & source preference, SSRF-safe web fetcher, paste/manual fallback, queue pipeline (ResearchCompanyJob, idempotency, concurrency), AI structuring with strict schema + fallback, storage/versioning, refresh & `researched_at` freshness, stale marking, service interface for downstream Interview/Cover-Letter consumers, security (prompt-injection, SSRF, size/type limits) and audit considerations.
- `company-research-ui`: Opportunity detail frontend experience for Company Research — states (not researched / researching / completed / failed / limited), structured brief presentation, fact vs. inference rendering, per-section sources, refresh action, staleness/age display, accessible loading/empty/error/retry handling.
- `safe-web-fetch`: Reusable server-side SSRF-safe fetcher utility — HTTPS enforcement, blocklist (loopback, private, link-local, metadata), DNS validation, redirect revalidation & limit, timeout, size & content-type allowlisting, scheme deny, safe user-agent, failure encapsulation for pipeline reuse.

### Modified Capabilities

- `opportunity-detail-ui`: Extend saved-opportunity detail page to host the Company Research section (layout integration, sticky rail interaction unaffected) without changing other data or mutation actions.
- `ingestion-pipeline`: Reference clarification that Company association may occur at `JobOpportunity` confirmation time via normalized identity reuse when reliable.

- **Risks & mitigations:**
  - AI hallucination / fabricated citations → strict schema + citation-required validation + fallback deterministic brief + source-preference tests.
  - SSRF bypass via DNS rebinding / redirect → per-hop IP validation, no follow-redirect without re-check, Host header pinning, limited redirects.
  - Duplicate Company records from variant names → deterministic normalization (trim, casefold, suffix stripping, domain canonicalization) with ambiguous-name guard; never fuzzy auto-merge.
  - Long AI/fetch blocking request → mandatory async + timeout + size caps + circuit to `failed`/`limited`.
  - Stale research presented as current → freshness threshold + UI staleness badge + manual refresh; no silent overwrite without timestamp bump.
- **Assumptions:** `companies` table exists and is unused for research; `JobOpportunity.company_id` exists but is nullable/unpopulated; confirmation flow can set `company_id` opportunistically without blocking confirmation; existing `RequestIdContext` + problem-details renderer can be reused.
