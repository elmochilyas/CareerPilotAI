## MODIFIED Requirements

### Requirement: FQ-FRONT-001 — Centralized API client

The frontend SHALL use Axios with credentials enabled and a centralized RFC 9457 error mapper. TanStack Vue Query SHALL manage server state. The frontend API client SHALL centrally generate and attach an `X-Request-ID` header to outgoing API requests; individual feature modules SHALL NOT implement their own request-ID generation or header injection.

#### Scenario: Axios client configured for Sanctum
- **WHEN** the application sends an API request
- **THEN** Axios SHALL send credentials (`withCredentials: true`) and the `XSRF-TOKEN` cookie

#### Scenario: Problem-detail error mapping
- **WHEN** the API returns an RFC 9457 error
- **THEN** a helper function SHALL parse the error response into a typed `ProblemDetail` object

#### Scenario: Request ID attached centrally
- **WHEN** any feature module issues an API request through the centralized client
- **THEN** the request carries an `X-Request-ID` header generated by the client layer without feature-specific code

#### Scenario: No per-feature request-ID duplication
- **WHEN** the codebase is inspected for request-ID generation logic
- **THEN** exactly one shared implementation exists in the API client layer and feature modules reference it (or rely on the interceptor) rather than duplicating it
